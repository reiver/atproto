How-To Backup an ATProto PDS: A Developers' Guide

com.atproto.sync.getRepo com.atproto.sync.listBlobs com.atproto.sync.getBlob

by Charles Iliya Krempeaux

This article goes over how-to backup an AT-Protocol (ATProto) Personal Data Server (PDS) from a computer-programming point-of-view.

Backing up an ATProto PDS involves downloading 2 types things: the repository, and BLOBs. There will be 1 repository to download. And, there will potentially be many BLOBs to download.

The repository contains things such as: posts, likes, followers, etc.

BLOBs are things such as: images, videos, etc.

To backup a PDS you will need to download both of these — the repository, and BLOBs.

Backing up an ATProto PDS involves 3 XRPC API end-points:

com.atproto.sync.getRepo

downloads the ATProto PDS's repository as a single CAR file.

com.atproto.sync.listBlobs

lists out all the BLOBs that are inside an ATProto PDS.

com.atproto.sync.getBlob

downloads a single BLOB that is inside an ATProto PDS.

Let's look at how each of these is used in more detail.

Step 1 of 3: Download Repository

The first step when backing up an ATProto PDS is download the repository. The repository is downloaded as a single file — a CAR (Content Addressable Archive) file.

(Remember, this will not download the BLOBs. You still need to download the BLOBs separate from this step.)

To download the repository as a CAR (Content Addressable Archive) file you call the ATProto com.atproto.sync.getRepo XRPC API end-point. For example: 


GET /xrpc/com.atproto.sync.getRepo?did={PUT_DID_HERE}
