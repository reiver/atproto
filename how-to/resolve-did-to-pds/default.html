How-To Resolve a DID (decentralized identifier) to a PDS (personal data server)

https://plc.directory/ /.well-known/did.json #atproto_pds

by Charles Iliya Krempeaux

This article goes over how-to resolve an AT-Protocol (ATProto) decentralized identifier (DID) to a Personal Data Server (PDS) from a computer-programming point-of-view.

For example, resolving the DID: 


did:plc:scewmn2pl3oz36mxme2b6czz

To the PDS: 


https://blacksky.app

A user's PDS is the server where that user's data lives — their posts, likes, follows, images, etc. If you want to read a user's data directly (rather than through some other service), you need to know where their PDS is.

A user can move from one PDS to another. But, (for better or worse) their DID stays the same. So, you should not assume a user's PDS never changes — you look it up, using the DID.

(If what you have is a handle — such as reiver.blacksky.team — rather than a DID, then first see: How-To Resolve a Handle to a DID (decentralized identifier).)

Two Steps

Resolving a DID to a PDS has 2 steps:

  1. resolve the DID to a DID document, and
  2. find the PDS inside of the DID document.

A DID document is a JSON document. It contains information about the DID — including the user's handle, the user's public-key, and the location of the user's PDS.

Let's look at each of these steps in more detail.

Step 1: Resolve the DID to a DID Document

How you get the DID document depends on the DID method.

The DID method is the part of the DID between the first colon and the second colon:

At the time of writing, ATProto supports 2 DID methods:

  • did:plc
  • did:web

Most ATProto users have a did:plc. But, your code needs to support both.

If you get a DID with any other DID method — such as did:key — then resolution has failed. (It is an “unsupported DID method”.)

did:plc

To resolve a did:plc to a DID document, make an HTTPS GET request to the PLC directory, with the whole DID as the path: 


https://plc.directory/DID

For example, for the DID did:plc:scewmn2pl3oz36mxme2b6czz, the URL is: 


https://plc.directory/did:plc:scewmn2pl3oz36mxme2b6czz

did:web

A did:web is based on an Internet domain. For example: 


did:web:genco.me

To resolve a did:web to a DID document, take the Internet domain from the DID (the part after did:web:), and make an HTTPS GET request to this URL: 


https://DOMAIN/.well-known/did.json

A few rules:

  • The general did:web specification allows DIDs with paths in them — for example, did:web:example.com:user:alice. ATProto does not support these. Only the Internet domain form (such as did:web:genco.me) is supported.
  • The general did:web specification also allows a port number, with the colon percent-encoded — for example, did:web:localhost%3A2583. ATProto only allows this for localhost, during development and testing.

Check the ID

Whichever DID method was used, check that the id field of the DID document is the same as the DID you asked for.

If they are not the same, then resolution has failed.

(Note that DIDs are case-sensitive. So, compare them exactly. Do not convert them to lower-case, like you would with a handle.)

Step 2: Find the PDS in the DID Document

Inside of the DID document is a field named service. It is a list (a JSON array).

Look through that list for the first entry where:

  • the id ends with #atproto_pds, and
  • the type is AtprotoPersonalDataServer.

The serviceEndpoint of that entry is the URL of the PDS:

A few rules:

  • Notice it says the id ends with #atproto_pds. The id might be written in short form — "#atproto_pds". Or, it might be written in long form, with the DID in front of it — "did:web:example.com#atproto_pds". Your code needs to handle both.
  • If there is more than one matching entry, use the first one, and ignore the others.
  • The serviceEndpoint should be just a scheme, a host, and (optionally) a port — such as https://blacksky.app. No path.
  • If there is no matching entry, then the account has no PDS. The specification says such an account “is likely broken”.

(A did:plc and a did:web both have the same kind of DID document. So, this step is the same for both.)

Summary

To resolve an ATProto DID to a PDS:

  1. Get the DID document:
    • for a did:plc, GET https://plc.directory/DID,
    • for a did:web, GET https://DOMAIN/.well-known/did.json,
    • for anything else, fail.
  2. Check that the DID document's id is the same as the DID.
  3. In the service list, find the first entry whose id ends with #atproto_pds and whose type is AtprotoPersonalDataServer.
  4. That entry's serviceEndpoint is the PDS.
